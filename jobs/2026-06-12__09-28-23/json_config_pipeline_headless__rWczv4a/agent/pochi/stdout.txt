# libGDX Headless: JSON Config Pipeline ## Background libGDX bundles its own reflection-free JSON utilities (`com.badlogic.gdx.utils.JsonReader`, `com.badlogic.gdx.utils.JsonValue`, `com.badlogic.gdx.utils.Json`) and a cross-platform file API (`Gdx.files` / `FileHandle`). The headless backend (`com.badlogicgames.gdx:gdx-backend-headless`) lets these utilities run on a server, in a CI runner, or inside a test harness without any OpenGL context, because it replaces `Graphics`/`Audio`/`Input` with mocks but leaves `Gdx.files`, the math and collections classes, and the `Json*` utilities fully functional. See [libGDX File Handling](https://libgdx.com/wiki/file-handling) and [Reading and writing JSON](https://libgdx.com/wiki/utils/reading-and-writing-json) for the relevant APIs. ## How It Works

1. **Launcher** parses `--config=<path>`, creates a `HeadlessApplication` with `updatesPerSecond = -1` (no render loop), and blocks on a `CountDownLatch` signaled in `dispose()` so stdout/stderr are always flushed before the JVM exits.

2. **ConfigListener** uses `Gdx.files.absolute(path)` to load the file, `JsonReader().parse()` to build the DOM, then walks the `JsonValue` tree validating all required fields, types, and constraints. On success it prints the 5-line summary; on failure it prints `Error: invalid config: <reason>` to stderr and sets the error flag.

3. The launcher reads the error flag after the latch and calls `System.exit(0)` or `System.exit(1)` accordingly.

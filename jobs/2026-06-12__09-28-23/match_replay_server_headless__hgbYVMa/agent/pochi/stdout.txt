### Project Structure
The project is organized as a multi-module Gradle project with the following layout:
- `settings.gradle`: Configures the multi-module build including `core` and `server` modules.
- `build.gradle`: Root-level build configuration defining JVM toolchain (Java 17) and Sonatype/Maven Central repositories.
- `gradlew`: Gradle wrapper configured for non-interactive use.
- `core/`: Shared simulation module with a dependency on `gdx:1.14.2` (no backend dependencies).
  - `Player.java`: Models player state (ID, initial position, current position).
  - `CommandType.java`: Enumeration of commands (`MOVE_UP`, `MOVE_DOWN`, `MOVE_LEFT`, `MOVE_RIGHT`, `NOOP`).
  - `Command.java`: Models a command at a specific tick for a specific player.
  - `CommandProvider.java`: A decoupled interface for retrieving commands per tick.
  - `Simulation.java`: Contains the deterministic grid-world simulation logic, parsing, and canonical state hashing.
- `server/`: Headless launcher module with dependencies on `gdx-backend-headless:1.14.2` and `gdx-platform:1.14.2:natives-desktop`.
  - `ReplayInput.java`: Subclass of `MockInput` implementing `CommandProvider` to expose commands to the simulation and replace `Gdx.input`.
  - `ServerLauncher.java`: The main entry point that loads the match log, drives the headless application loop frame-by-frame, and outputs the transcript.

### Key Implementation Details
1. **Deterministic Simulation**: All movement, clamping, and command-ordering logic lives in the `core` module. At each tick, active commands are sorted by `player_id` ascending and applied sequentially.
2. **Headless Application Integration**: The launcher initializes a `HeadlessApplication` with an `updatesPerSecond` of `1000` to run the simulation quickly. It replaces `Gdx.input` with a custom `ReplayInput` subclass to feed commands to the simulation.
3. **Synchronous Thread Termination**: `Gdx.app.exit()` is called asynchronously once all ticks have been simulated. Reflection is used to `join()` the `HeadlessApplication.mainLoopThread` to guarantee that the simulation has fully finished before the transcript is written.
4. **Precise Output Validation**: The written transcript is a UTF-8 JSON file containing the exact fields (`world`, `players`, `totalTicks`, `commandsApplied`, `stateHash`) and matching types. The `stateHash` is computed as the SHA-256 of the canonical state string: `W=<width>;H=<height>;P=<id1>:<x1>,<y1>|...`.
5. **No Extra Dependencies**: No graphical backend (like LWJGL3) is included in the dependencies, and only the pinned libGDX `1.14.2` version is used.

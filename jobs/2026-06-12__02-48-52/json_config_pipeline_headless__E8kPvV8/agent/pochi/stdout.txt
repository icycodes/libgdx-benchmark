# libGDX Headless: JSON Config Pipeline ## Background libGDX bundles its own reflection-free JSON utilities (`com.badlogic.gdx.utils.JsonReader`, `com.badlogic.gdx.utils.JsonValue`, `com.badlogic.gdx.utils.Json`) and a cross-platform file API (`Gdx.files` / `FileHandle`). The headless backend (`com.badlogicgames.gdx:gdx-backend-headless`) lets these utilities run on a server, in a CI runner, or inside a test harness without any OpenGL context, because it replaces `Graphics`/`Audio`/`Input` with mocks but leaves `Gdx.files`, the math and collections classes, and the `Json*` utilities fully functional. See [libGDX File Handling](https://libgdx.com/wiki/file-handling) and [Reading and writing JSON](https://libgdx.com/wiki/utils/reading-and-writing-json) for the relevant APIs. In this task you will build a small libGDX 1.14.2 project around the **headless** backend that turns a game-config JSON file into a deterministic summary. The launcher must read the configuration through `Gdx.files`, parse it with libGDX's `JsonReader`/`JsonValue`, compute a few aggregate statistics, print them to stdout, and exit cleanly via `Gdx.app.exit()`. ## Requirements - Create a Gradle (Java 17) project at `/home/user/gdx-game` that depends on libGDX `1.14.2` (`gdx`, `gdx-backend-headless`, `gdx-platform:natives-desktop`). - Implement a libGDX `ApplicationListener` (or `ApplicationAdapter`) whose `create()` method: 1. Obtains a `FileHandle` for the config path via `Gdx.files.absolute(path)`. 2. Parses the file's contents with libGDX's `JsonReader`/`JsonValue` DOM (you may also use `com.badlogic.gdx.utils.Json` if you prefer reflection-based mapping). 3. Computes the summary described below and writes it to stdout. 4. Calls `Gdx.app.exit()` so the headless main loop terminates cleanly. - Produce a runnable launcher (using the Gradle `application` plugin) at `/home/user/gdx-game/build/install/gdx-game/bin/gdx-game` that accepts a `--config=` argument and runs the application on a `HeadlessApplication`. - The launcher's `main` thread must wait for the `HeadlessApplication` to finish (e.g., by joining its main-loop thread) before the JVM exits, so that summary or error lines are always flushed before the process returns. ### Config file format - UTF-8 text file containing a single JSON document. - Root must be a JSON object with the following fields: - `"game"`: non-empty string identifying the game. - `"levels"`: JSON array (possibly empty) of level objects. Each level object must contain: - `"name"`: non-empty string. - `"enemies"`: JSON array (possibly empty) of enemy objects. Each enemy object must contain: - `"type"`: non-empty string. - `"hp"`: non-negative integer. - The order of levels in the array and of enemies inside each level array determines iteration order (used to break ties for the strongest enemy). ### Successful output format When the config parses successfully, the launcher must print exactly the following five lines to stdout, in this order, each terminated by a newline: ``` Game: <game> Levels: <level-count> Enemies: <total-enemy-count> Total HP: <sum-of-hp> Strongest enemy: <answer> ``` Where: - `<game>` is the value of the root `"game"` field. - `<level-count>` is the number of entries in the `"levels"` array. - `<total-enemy-count>` is the total number of enemies across all levels. - `<sum-of-hp>` is the sum of every enemy's `"hp"` value across all levels (use 64-bit arithmetic; the result fits in a `long`). - `<answer>` is `<type> (<hp>)` for the single enemy with the highest `"hp"`. Iterate levels in array order, and within each level iterate enemies in array order; the first enemy whose `"hp"` is strictly greater than the current best wins. If no enemy exists (every level has an empty `"enemies"` array, or there are no levels at all), `<answer>` must be the literal string `none`. The launcher must exit with status `0` on a successful run. ### Error handling If the configuration cannot be processed (file does not exist, file is not valid JSON, a required field is missing, a field has the wrong JSON type, `"game"` or any `"name"`/`"type"` is empty, or an `"hp"` value is negative), the launcher must: - Print a single line to **stderr** in the form `Error: invalid config: <reason>`, where `<reason>` is any short human-readable diagnostic message. - Not print any of the five `Game:`/`Levels:`/`Enemies:`/`Total HP:`/`Strongest enemy:` lines to stdout. - Exit with a non-zero status code. ## Implementation Hints - Pin `gdxVersion=1.14.2`. The required Maven coordinates and headless backend recipe are summarised in the libGDX docs ([Dependency management with Gradle](https://libgdx.com/wiki/articles/dependency-management-with-gradle), [Headless backend source](https://github.com/libgdx/libgdx/blob/master/backends/gdx-backend-headless/src/com/badlogic/gdx/backends/headless/HeadlessApplication.java)). - The Gradle `application` plugin gives you a turnkey launcher: configure `mainClass` and run `./gradlew installDist` to produce `build/install/<projectName>/bin/<projectName>`. - `HeadlessApplication` runs the listener on its own thread, so block the launcher's `main` thread (e.g., by joining the headless main-loop thread) until the application has exited; otherwise the JVM may quit before the summary or error line is printed. - The headless backend is sensitive to OpenGL calls -- do **not** touch `Gdx.gl*` anywhere in your code. - `JsonValue` already exposes traversal helpers like `get(String)`, `getString(String, def)`, `getInt(String, def)`, `iterator()`, and `isArray()/isObject()/isNumber()/isString()` which make field validation straightforward. See [Reading and writing JSON](https://libgdx.com/wiki/utils/reading-and-writing-json). - Bootstrap the Gradle wrapper with `gradle wrapper --gradle-version 8.10 --distribution-type bin` so reproducible builds are possible from the project root. - Catch parse / validation exceptions, route the diagnostic line to `System.err`, and signal failure to the launcher (e.g., set a flag the launcher's `main` reads after `join()` and use `System.exit(<non-zero>)`). ## Acceptance Criteria - Project path: `/home/user/gdx-game`. - After running `./gradlew --no-daemon --quiet installDist` from the project root, the launcher script `/home/user/gdx-game/build/install/gdx-game/bin/gdx-game` must exist and be executable. - Command: `/home/user/gdx-game/build/install/gdx-game/bin/gdx-game --config=<path>` - The command must accept the `--config=<path>` argument (equals form) where `<path>` is the absolute path to a JSON config file conforming to the format above. - Successful runs must: - Print to stdout exactly the five lines `Game: <game>`, `Levels: <n>`, `Enemies: <m>`, `Total HP: <sum>`, `Strongest enemy: <answer>` (in that order). `<answer>` follows the `<type> (<hp>)` shape, or is the literal `none` when there are no enemies. - Exit with status code `0`. - Failed runs (file missing, malformed JSON, required field missing, wrong field type, empty `"game"`/`"name"`/`"type"`, or negative `"hp"`) must: - Print a single line to stderr starting with `Error: invalid config:`. - Not print any of the five summary lines to stdout. - Exit with a non-zero status code. - The application must use `com.badlogic.gdx.backends.headless.HeadlessApplication` to boot the listener, the config must be loaded through `Gdx.files`, and the JSON must be parsed by libGDX's bundled JSON utilities. ## How it works

**`Main.java`**
1. Parses `--config=<path>` from `args[]`.
2. Creates a `HeadlessApplicationConfiguration` (updatesPerSecond = -1).
3. Boots `new HeadlessApplication(app, cfg)` – listener runs on its own thread named `"HeadlessApplication"`.
4. Looks up that thread by name and **joins it**, so the main thread blocks until `Gdx.app.exit()` is fully processed and all output is flushed.
5. Reads `app.failed` and calls `System.exit(0)` or `System.exit(1)`.

**`ConfigSummaryApp.java`** (`create()` method)
1. Opens the config via `Gdx.files.absolute(path)` → `FileHandle`.
2. Reads the text and parses it with `new JsonReader().parse(text)` (libGDX built-in DOM).
3. Validates every required field (`game`, `levels[].name`, `levels[].enemies[].type`, `levels[].enemies[].hp`) – type, presence, and value constraints.
4. Computes level count, total enemies, total HP (64-bit), and strongest enemy (first with strictly highest HP, array-order tie-break).
5. Prints exactly the five required lines to stdout, then calls `Gdx.app.exit()`.
6. On any error sets `failed = true`, prints `Error: invalid config: <reason>` to stderr, and still calls `Gdx.app.exit()`.

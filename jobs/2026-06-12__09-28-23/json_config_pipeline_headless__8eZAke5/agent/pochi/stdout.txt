# libGDX Headless: JSON Config Pipeline ## Background libGDX bundles its own reflection-free JSON utilities (`com.badlogic.gdx.utils.JsonReader`, `com.badlogic.gdx.utils.JsonValue`, `com.badlogic.gdx.utils.Json`) and a cross-platform file API (`Gdx.files` / `FileHandle`). The headless backend (`com.badlogicgames.gdx:gdx-backend-headless`) lets these utilities run on a server, in a CI runner, or inside a test harness without any OpenGL context, because it replaces `Graphics`/`Audio`/`Input` with mocks but leaves `Gdx.files`, the math and collections classes, and the `Json*` utilities fully functional. See [libGDX File Handling](https://libgdx.com/wiki/file-handling) and [Reading and writing JSON](https://libgdx.com/wiki/utils/reading-and-writing-json) for the relevant APIs. In this task you will build a small libGDX 1.14.2 project around the **headless** backend that turns a game-config JSON file into a deterministic summary. The launcher must read the configuration through `Gdx.files`, parse it with libGDX's `JsonReader`/`JsonValue`, compute a few aggregate statistics, print them to stdout, and exit cleanly via `Gdx.app.exit()`. ## Requirements - Create a Gradle (Java 17) project at `/home/user/gdx-game` that depends on libGDX `1.14.2` (`gdx`, `gdx-backend-headless`, `gdx-platform:natives-desktop`). - Implement a libGDX `ApplicationListener` (or `ApplicationAdapter`) whose `create()` method: 1. Obtains a `FileHandle` for the config path via `Gdx.files.absolute(path)`. 2. Parses the file's contents with libGDX's `JsonReader`/`JsonValue` DOM (you may also use `com.badlogic.gdx.utils.Json` if you prefer reflection-based mapping). 3. Computes the summary described below and writes it to stdout. 4. Calls `Gdx.app.exit()` so the headless main loop terminates cleanly. - Produce a runnable launcher (using the Gradle `application` plugin) at `/home/user/gdx-game/build/install/gdx-game/bin/gdx-game` that accepts a `--config=` argument and runs the application on a `HeadlessApplication`. - The launcher's `main` thread must wait for the `HeadlessApplication` to finish (e.g., by joining its main-loop thread) before the JVM exits, so that summary or error lines are always flushed before the process returns. ### Config file format - UTF-8 text file containing a single JSON document. - Root must be a JSON object with the following fields: - `"game"`: non-empty string identifying the game. - `"levels"`: JSON array (possibly empty) of level objects. Each level object must contain: - `"name"`: non-empty string. - `"enemies"`: JSON array (possibly empty) of enemy objects. Each enemy object must contain: - `"type"`: non-empty string. - `"hp"`: non-negative integer. - The order of levels in the array and of enemies inside each level array determines iteration order (used to break ties for the strongest enemy). ### Successful output format When the config parses successfully, the launcher must print exactly the following five lines to stdout, in this order, each terminated by a newline: ``` Game: <game> Levels: <level-count> Enemies: <total-enemy-count> Total HP: <sum-of-hp> Strongest enemy: <answer> ``` Where: - `<game>` is the value of the root `"game"` field. - `<level-count>` is the number of entries in the `"levels"` array. - `<total-enemy-count>` is the total number of enemies across all levels. - `<sum-of-hp>` is the sum of every enemy's `"hp"` value across all levels (use 64-bit arithmetic; the result fits in a `long`). - `<answer>` is `<type> (<hp>)` for the single enemy with the highest `"hp"`. Iterate levels in array order, and within each level iterate enemies in array order; the first enemy whose `"hp"` is strictly greater than the current best wins. If no enemy exists (every level has an empty `"enemies"` array, or there are no levels at all), `<answer>` must be the literal string `none`. The launcher must exit with status `0` on a successful run. ### Error handling If the configuration cannot be processed (file does not exist, file is not valid JSON, a required field is missing, a field has the wrong JSON type, `"game"` or any `"name"`/`"type"` is empty, or an `"hp"` value is negative), the launcher must: - Print a single line to **stderr** in the form `Error: invalid config: <reason>`, where `<reason>` is any short human-readable diagnostic message. - Not print any of the five `Game:`/`Levels:`/`Enemies:`/`Total HP:`/`Strongest enemy:` lines to stdout. - Exit with a non-zero status code. ## Implementation Hints - Pin `gdxVersion=1.14.2`.

# libGDX Headless: Box2D Scripted Impulse Simulator ## Background libGDX ships a non-rendering backend (`com.badlogicgames.gdx:gdx-backend-headless`) that swaps the live `Graphics`/`Input`/`Audio` implementations for mocks so that an `ApplicationListener` can be driven from a server, CI runner, or test harness. libGDX also bundles a JNI wrapper around the Box2D physics engine (`com.badlogicgames.gdx:gdx-box2d` plus the `gdx-box2d-platform:natives-desktop` native artifact). Because Box2D itself never touches OpenGL, it pairs cleanly with the headless backend and is the canonical way to run a deterministic physics simulation inside a JUnit-style harness or a CI job. In this task you will build a small libGDX `1.14.2` project that boots a `HeadlessApplication`, creates a Box2D `World` plus a single dynamic body, replays a scripted sequence of linear impulses against it, advances the world by a fixed number of physics steps, and prints the body's final position. ## Requirements * Create a Gradle (Java 17) project at `/home/user/gdx-game` that depends on libGDX `1.14.2`: * `com.badlogicgames.gdx:gdx:1.14.2` * `com.badlogicgames.gdx:gdx-backend-headless:1.14.2` * `com.badlogicgames.gdx:gdx-platform:1.14.2:natives-desktop` * `com.badlogicgames.gdx:gdx-box2d:1.14.2` * `com.badlogicgames.gdx:gdx-box2d-platform:1.14.2:natives-desktop` * Implement a libGDX `ApplicationListener` (or `ApplicationAdapter`) that drives the physics simulation on the headless main-loop thread. * Produce a runnable launcher (using the Gradle `application` plugin) at `/home/user/gdx-game/build/install/gdx-game/bin/gdx-game` that accepts a single `--scenario=` argument and runs the simulation on a `HeadlessApplication`. * After every scripted step has executed, print exactly one line `Final position: (<x>, <y>)` to stdout, formatted as described in the Acceptance Criteria below. * Call `Gdx.app.exit()` once the simulation is complete so the headless main loop terminates cleanly, and block the launcher's `main` thread until the application has finished (the JVM must not return before the final position has been printed). ### Scenario file format * UTF-8 text file. Lines are case-sensitive for the leading keyword and trimmed of surrounding whitespace. * Blank lines are skipped. Lines starting with `#` are treated as comments and skipped. * All numeric values are decimal floats (Java `Float.parseFloat` parses every numeric token used below). * Keyword grammar (header order is free, but uniqueness rules below apply): * `GRAVITY <gx> <gy>` — world gravity in m/s². Required exactly once. * `BODY <x0> <y0>` — initial position of the single dynamic body. Required exactly once. * `MASS <m>` — optional. If present (at most once), override the body's mass to exactly `m` kg using `Body.setMassData(...)`. If absent, leave the auto-computed mass produced by the body's fixture. * `IMPULSE <step> <ix> <iy>` — zero or more entries. Apply linear impulse `(ix, iy)` (in N·s) at the body's world center *before* physics step `<step>` runs. `<step>` is a non-negative integer, 0-indexed against the very first physics step that the simulation executes. * `STEPS <n>` — total number of physics steps to advance. Required exactly once. `<n>` is a non-negative integer. * The body itself is fixed: dynamic body type, a single circular fixture of radius `0.5` m, density `1.0`, friction `0`, restitution `0`, linear damping `0`, angular damping `0`. No other bodies (static, kinematic, dynamic) exist in the world. * Time step is fixed: `dt = 1f / 60f` seconds, velocity iterations `6`, position iterations `2` (i.e., `world.step(1f/60f, 6, 2)`). * Per-step ordering, for every step index `k` from `0` to `n-1`: 1. Apply every `IMPULSE k <ix> <iy>` (in the order they appeared in the file) to the body's world center, waking the body. 2. Call `world.step(1f/60f, 6, 2)`. * Any malformed scenario file (missing required `GRAVITY`/`BODY`/`STEPS`, unknown keyword, non-numeric token, duplicate `GRAVITY`/`BODY`/`MASS`/`STEPS`, negative `STEPS`, or `IMPULSE` with a `<step>` outside `[0, STEPS)`) must cause the program to write a line beginning with `Error:` to stderr (the substring after `Error:` is free-form) and exit with a non-zero status code. In that case the program must **not** print a `Final position:` line on stdout. ## Implementation Hints * Pin `gdxVersion=1.14.2`. The Box2D Maven coordinates are documented in https://libgdx.com/wiki/articles/dependency-management-with-gradle#box2d-gradle. The headless backend and `HeadlessApplication` contract is documented in https://github.com/libgdx/libgdx/blob/master/backends/gdx-backend-headless/src/com/badlogic/gdx/backends/headless/HeadlessApplication.java and the https://libgdx.com/wiki/app/the-life-cycle. * Use the Gradle `application` plugin (configure `mainClass` and run `./gradlew installDist`) to produce `build/install/<projectName>/bin/<projectName>`. * `HeadlessApplication` runs the listener on its own thread, so block the launcher's `main` thread (e.g., by joining the headless main-loop thread or using a `CountDownLatch` fired from `dispose()`) until the application has exited; otherwise the JVM may quit before the simulation finishes. * The headless backend has no OpenGL context — do **not** touch `Gdx.gl*` anywhere in your code. Box2D itself does not require GL. * Bootstrap the Gradle wrapper non-interactively with `gradle wrapper --gradle-version 8.10 --distribution-type bin` so reproducible builds are possible from the project root. * Be sure to call `Body.applyLinearImpulse(impulse, body.getWorldCenter(), true)` so the body is woken when an impulse arrives at the first step, otherwise dormant bodies will ignore the impulse. * When `MASS` is present, build a `MassData` whose `mass` field is the requested value (you may leave `I` and `center` at their auto-computed values from `Body.getMassData()`) and call `body.setMassData(mass)`. * `Body.getPosition()` returns the body's world-center; that is what must be reported. * Consider setting `HeadlessApplicationConfiguration.updatesPerSecond = 0` so the listener's `render()` is called as fast as possible — there is no need to throttle, since the simulation must produce a single deterministic answer. ## Acceptance Criteria * Project path: `/home/user/gdx-game`. * After running `./gradlew --no-daemon --quiet installDist` from the project root, the launcher script `/home/user/gdx-game/build/install/gdx-game/bin/gdx-game` must exist and be executable. * Command: `/home/user/gdx-game/build/install/gdx-game/bin/gdx-game --scenario=<path>` where `<path>` is the absolute path to a scenario file conforming to the format above. * Successful runs (the scenario file parses cleanly) must: * Print exactly one line of the form `Final position: (<x>, <y>)` to stdout, where `<x>` and `<y>` are the final body coordinates formatted with the `Locale.ROOT` form of `%.4f` (i.e., four digits after the decimal point, `.` as separator, leading `-` for negatives).

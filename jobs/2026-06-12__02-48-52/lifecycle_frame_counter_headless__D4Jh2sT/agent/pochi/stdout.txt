## Key Implementation Details

### `FrameCounterApp.java`
- `create()` resets `frameCount = 0`
- `render()` increments the counter; when `frameCount >= targetFrames` it calls `stopLoop()`
- `dispose()` prints `FRAME_COUNT: <N>` to stdout

**Why `stopLoop()` uses reflection:**  
`Gdx.app.exit()` posts a Runnable onto the HeadlessApplication's queue. That queue is drained at the **top** of the next loop tick — *before* `render()` is called — so one extra `render()` fires after the exit is posted, producing `N+1` frames. The fix: after calling `Gdx.app.exit()` (for proper lifecycle-listener notification), also set `HeadlessApplication.running = false` via reflection immediately inside `render()`. The loop's `running` check fires immediately after `render()` returns, so no extra tick occurs and `dispose()` sees exactly `N`.

### `Main.java`
- Reads `N` from `args[0]`
- Sets `updatesPerSecond = 1000` so even `N=1000` completes in ~1 second
- Constructs `HeadlessApplication`, then retrieves the `mainLoopThread` field via reflection (it's a named field on `HeadlessApplication`) and calls `join()` — ensuring `dispose()` runs before `System.exit(0)`

### `build.gradle`
- Dependencies: `gdx:1.14.2`, `gdx-backend-headless:1.14.2`, `gdx-platform:1.14.2:natives-desktop` (the natives JAR is required to load `libgdx64.so` at runtime)
- `JavaExec` task named `run` with `standardOutput = System.out` and `errorOutput = System.err` so Gradle's `-q` flag doesn't swallow program output

### `run.sh`

# libGDX Headless XML Scene Graph Loader ## Background This task is about building a deterministic, CI-runnable command-line tool with the libGDX framework. libGDX ships a non-rendering **headless backend** (`com.badlogicgames.gdx:gdx-backend-headless`) that boots an `ApplicationListener` without an OpenGL context, plus a `Gdx.files`-backed `FileHandle` API and an `XmlReader` DOM parser in `com.badlogic.gdx.utils`. Your job is to implement a small libGDX 1.14.2 application that loads an XML file describing a 2D hierarchical **scene graph** (nodes with local transforms and children), uses `HeadlessApplication` to drive the lifecycle, parses the XML with libGDX's `XmlReader`, computes each node's **world-space transform** by composing the chain of parent transforms, and writes a deterministic, depth-first transcript of the resulting tree to an output file. ## Requirements * Use libGDX `1.14.2` with the `gdx-backend-headless` backend. The program must run with no OpenGL context; it must not call `Gdx.gl*` or instantiate `SpriteBatch`/`Texture`. * The project must be built and run with Gradle (the Gradle wrapper is already provided in the project). * The entry point must be runnable through Gradle as `./gradlew --no-daemon :app:run --quiet --args="--scene=<scene_xml_path> --output=<output_txt_path>"`, where: * `<scene_xml_path>` is an absolute path to an input XML file. * `<output_txt_path>` is an absolute path to which the program must write the transcript. * The program must boot a `HeadlessApplication` with `updatesPerSecond = 0` (run as fast as possible) and exit cleanly after the transcript is written (i.e., call `Gdx.app.exit()` and let the headless main loop join). * File I/O on both the scene XML and the output transcript must go through `Gdx.files.absolute(...)` so the file backend is exercised in headless mode. * The XML must be parsed with `com.badlogic.gdx.utils.XmlReader` (do not use `javax.xml`, DOM4J, JDOM, or other XML parsers). ## Input XML Format The XML describes a single rooted scene. A node may have any number of child `<node>` elements. ```xml <scene> <node name="root" x="10" y="20" rotation="0" scaleX="1" scaleY="1"> <node name="child" x="5" y="0" rotation="45" scaleX="1" scaleY="1"> <node name="leaf" x="3" y="3" rotation="0" scaleX="0.5" scaleY="0.5"/> </node> </node> </scene> ``` Rules: * The root element is `<scene>` and contains exactly one top-level `<node>`. * Each `<node>` element must have a `name` attribute. The optional numeric attributes (`x`, `y`, `rotation`, `scaleX`, `scaleY`) default to `0`, `0`, `0`, `1`, `1` respectively when absent. * `rotation` is expressed in **degrees** (counter-clockwise, libGDX convention). * All node names within a single parent are unique; names contain only `[A-Za-z0-9_]`. ## Transform Composition Rules For every node `N` with parent `P`, compute `N`'s world transform from its local `(x, y, rotation, scaleX, scaleY)` and `P`'s world transform as follows. The root node's parent is the identity transform (world position `(0,0)`, world rotation `0`, world scale `(1,1)`). 1. Scale the local offset by the parent's world scale: `lx = N.x * P.worldScaleX`, `ly = N.y * P.worldScaleY`. 2. Rotate the scaled offset by the parent's world rotation (in degrees, counter-clockwise): if `cos = cos(P.worldRotation)` and `sin = sin(P.worldRotation)`, then `rx = lx*cos - ly*sin`, `ry = lx*sin + ly*cos`. 3. Translate by the parent's world position: `N.worldX = P.worldX + rx`, `N.worldY = P.worldY + ry`. 4. Compose rotation: `N.worldRotation = P.worldRotation + N.rotation`. 5. Compose scale (component-wise): `N.worldScaleX = P.worldScaleX * N.scaleX`, `N.worldScaleY = P.worldScaleY * N.scaleY`. Trigonometry must use degrees (you may use `com.badlogic.gdx.math.MathUtils.cosDeg/sinDeg` or `Math.cos`/`Math.sin` with manual degree-to-radian conversion). ## Output Transcript Format The program must write the output file with these properties: * One line per node, in **pre-order depth-first traversal** (each parent is emitted before its children). Children must be visited in the same order they appear in the XML. * Each line has exactly the following six tab-separated fields, with values formatted using `%.4f` and `java.util.Locale.ROOT`: ``` <dotted_path>\tworldX=<%.4f>\tworldY=<%.4f>\tworldRotationDeg=<%.4f>\tworldScaleX=<%.4f>\tworldScaleY=<%.4f> ``` Where `<dotted_path>` is the path from the root node down to this node, with names joined by `.` (the root is its own name, e.g. `root`; the leaf in the sample above is `root.child.leaf`). * Lines are terminated by a single `\n`. The file ends with a trailing newline after the last node. * `worldRotationDeg` is the raw composed value (do **not** normalize to `[0, 360)`). * The output file must be written through `Gdx.files.absolute(<output_txt_path>).writeString(transcript, false, "UTF-8")` (or equivalent libGDX FileHandle write). ## Implementation Hints * Use `gdx-liftoff`-style multi-module Gradle layout is **not** required; a single `app` module that depends on `com.badlogicgames.gdx:gdx:1.14.2`, `com.badlogicgames.gdx:gdx-backend-headless:1.14.2`, and `runtimeOnly com.badlogicgames.gdx:gdx-platform:1.14.2:natives-desktop` is sufficient. * The Gradle `application` plugin lets you wire `mainClass` and forward `--args` to `JavaExec`. Forward the program arguments to your `ApplicationListener` via constructor parameters before constructing `HeadlessApplication`. * Use `com.badlogic.gdx.utils.XmlReader` and recurse on `XmlReader.Element#getChildrenByName("node")`. Use `Element#getFloatAttribute(name, defaultValue)` for the optional numeric attributes. * Build the transcript in memory (e.g., in a `StringBuilder`) inside `create()`, write it through `Gdx.files.absolute(...)`, and call `Gdx.app.exit()`. Wait for the main loop thread by holding a reference to the `HeadlessApplication` instance (do not return from `main` before the application's main loop thread joins). * Refer to the official docs for the headless backend, `XmlReader`, `Gdx.files`, and `MathUtils` (see the libGDX wiki and Javadoc). ## Acceptance Criteria * Project path: /home/user/gdx-scene-loader * Command: cd /home/user/gdx-scene-loader && ./gradlew --no-daemon :app:run --quiet --args="--scene=\<scene\_xml\_path> --output=\<output\_txt\_path>" * The Gradle build must declare a dependency on `com.badlogicgames.gdx:gdx-backend-headless:1.14.2` and run the program through `HeadlessApplication`. * The XML must be parsed with `com.badlogic.gdx.utils.XmlReader`. * The output file at `<output_txt_path>` must exist after the command completes. * The output file must contain one line per scene-graph node in pre-order DFS, using the exact format `<dotted_path>\tworldX=<%.4f>\tworldY=<%.4f>\tworldRotationDeg=<%.4f>\tworldScaleX=<%.4f>\tworldScaleY=<%.4f>` (tab-separated, locale-independent `.` decimal separator). * Every numeric value must be rounded to 4 decimal places using `Locale.ROOT`. * The number of output lines must equal the number of `<node>` elements in the input XML. * The program must exit with status `0` when the run succeeds. * The program must not invoke any OpenGL APIs (verified indirectly by running under the headless backend with no display).

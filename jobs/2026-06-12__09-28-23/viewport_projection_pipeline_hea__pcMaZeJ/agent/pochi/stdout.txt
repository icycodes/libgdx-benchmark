# libGDX Headless Viewport Projection Pipeline ## Background Games built with libGDX commonly use an `OrthographicCamera` paired with a `Viewport` (e.g., `FitViewport`, `ExtendViewport`, `StretchViewport`, `ScreenViewport`) so that the same world coordinates render consistently across many screen sizes. The headless backend ships with `MockGraphics`, so no real OpenGL context exists, but the math behind `Camera`/`Viewport`/`Vector3` is plain Java and runs perfectly under `HeadlessApplication`. Your job is to build a deterministic CLI tool — `viewport-projector` — that boots libGDX's headless backend, replays a scripted sequence of window resize events and world points read from a JSON scenario file, and writes the resulting screen-space coordinates (and an unproject round-trip check) to an output log file. The tool will be used by an automated grader to validate viewport math without ever touching a GPU. ## Requirements * Create a Gradle multi-module libGDX project under `/home/user/myproject` with a `core` module that contains the projection logic and a `headless` module that boots the headless backend. * Pin libGDX to version `1.14.2` (`com.badlogicgames.gdx:gdx:1.14.2`, `com.badlogicgames.gdx:gdx-backend-headless:1.14.2`, `com.badlogicgames.gdx:gdx-platform:1.14.2:natives-desktop`). * The headless module's launcher class must accept two command-line arguments: `--scenario=<path-to-json>` and `--output=<path-to-log>`. * The launcher must boot `HeadlessApplication` with `HeadlessApplicationConfiguration.updatesPerSecond = 60` and run the scenario to completion before calling `Gdx.app.exit()`. The Java process must terminate cleanly (exit code 0) after the headless main-loop thread finishes. * The scenario file is a JSON document with the following stable schema (parsed via libGDX's `com.badlogic.gdx.utils.Json`/`JsonReader` or any equivalent JSON library): ```json { "viewport": "fit" | "extend" | "stretch" | "screen", "worldWidth": <number>, "worldHeight": <number>, "cameraPosition": { "x": <number>, "y": <number> }, "frames": [ { "frame": <int>, "resize": { "width": <int>, "height": <int> }, "points": [ { "x": <number>, "y": <number> } ] } ] } ``` * `viewport` selects which `Viewport` subclass to instantiate around an `OrthographicCamera`. * `worldWidth` / `worldHeight` are the virtual viewport dimensions passed to the viewport constructor. For `"screen"` the values are ignored. * `cameraPosition` sets `camera.position.x` / `camera.position.y` once during `create()` (z is always 0). * Each entry of `frames` describes one render tick. The launcher must process them in ascending `frame` order. When `resize` is present, call `viewport.update(width, height, true)` BEFORE projecting that frame's points. The `points` list (zero or more) contains world-space points to project. * For every point in every frame, write exactly one line to the output log in the format: ``` FRAME <frame> PROJECT (<wx>,<wy>) -> (<sx>,<sy>) ``` where `<wx>`, `<wy>`, `<sx>`, `<sy>` are formatted with `String.format(java.util.Locale.US, "%.3f", value)` (three decimals, US locale, dot decimal separator, no thousands separator). `<sx>`/`<sy>` are computed via `viewport.project(new Vector2(wx, wy))`. * After processing all frames, write one round-trip line per `(frame, point)` pair, in the same order as the PROJECT lines, using the LAST applied viewport size: ``` ROUNDTRIP <frame> (<wx>,<wy>) -> (<rx>,<ry>) <STATUS> ``` where `<rx>`/`<ry>` come from `viewport.unproject(viewport.project(point))` (run on a fresh `Vector2` each time) and `<STATUS>` is the literal string `OK` if `|rx - wx| <= 0.01 && |ry - wy| <= 0.01`, otherwise `MISMATCH`. Use the same `%.3f` formatting for the numbers. * After the last ROUNDTRIP line, write a final line: ``` END frames= points=<M> ``` where `<N>` is the number of frames processed and `<M>` is the total number of points projected. * The launcher MUST NOT print any other lines to the output file. Diagnostic messages to stdout/stderr are allowed and ignored by the grader. * The tool must be invocable from the project root with: ```bash ./gradlew --no-daemon --console=plain headless:run --args="--scenario=<abs-path> --output=<abs-path>" ``` Each invocation must overwrite (not append to) the output file. ## Implementation Hints * Use `gradle wrapper --gradle-version 8.10 --distribution-type bin` to bootstrap the Gradle wrapper non-interactively. * A clean way to organise the project is `core` (contains a `ProjectionApp` implementing `ApplicationAdapter`) and `headless` (contains a `HeadlessLauncher` `main` method that parses args, loads the scenario, instantiates `ProjectionApp`, and starts `HeadlessApplication`).
